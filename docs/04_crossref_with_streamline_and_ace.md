# 04. streamline/nvidia-ace 스터디와 교차검증 — "핵심 IP는 닫고 배관만 연다" 패턴

## 1. 이미 관찰된 패턴 (선행 스터디 인용)

- `streamline-architecture-study/docs/01` §3(등급 a, 실측): Streamline은 MIT 라이선스로
  거의 전체가 진짜 오픈소스이지만, **DLSS-G(프레임 생성) 플러그인만 예외** — `sl_dlss_g.h`
  헤더만 공개되고 `source/plugins/sl.dlss_g/` 구현은 저장소에 존재하지 않음.
- `nvidia-ace-architecture-study`(참고, 자매 저장소): NVIGI 역시 벤더 중립 코어는
  공개하되 실제 추론 백엔드는 비공개.

## 2. DLSS5는 이 패턴의 극단형

이번 스터디(`docs/02`)에서 확인한 DLSS5는 같은 패턴이지만 한 단계 더 닫혀 있습니다:

| | Streamline의 DLSS-G | DLSS5 (공식 `NVIDIA/DLSS` 리포) |
|---|---|---|
| 구현 코드 | 비공개 | 비공개 (동일) |
| API 헤더 | **공개** (`sl_dlss_g.h`) | **비공개 수준** — 이 커밋 시점엔 헤더 자체가 없음(`docs/02` §2) |
| 배포 형태 | 프리빌드 DLL | 프리빌드 DLL 3종은 있으나 DLSS5용은 없음 |

즉 Streamline/NVIGI가 보여준 "핵심 IP는 닫고, 통합 배관(헤더/API)은 연다"는 전략에서,
DLSS5는 **아직 배관조차 안 열린 상태**입니다. 이걸 이 시리즈의 새로운 패턴으로 볼지,
아니면 단순히 "출시 직후라 SDK 동기화 지연"인지는 `docs/02` §3에서 이미 밝혔듯
등급 c(추정)로만 남깁니다 — 다음 SDK 리포 갱신을 확인해야 판가름납니다.

## 3. 화이트리스트 오버라이드도 같은 철학의 연장

`docs/06`에서 다루는 `ApplicationStorage.json` 기반 화이트리스트 시스템도 같은 맥락으로
읽을 수 있습니다: NVIDIA는 "어떤 게임에 어떤 기능을 켤지"를 **로컬 설정 파일 + 서버측
지문 DB(fingerprint.db)의 조합**으로 통제합니다. 이는 Streamline의 "코어는 공개, 특정
플러그인만 비공개"와 구조적으로 유사한 접근 — **기술 자체의 접근 제어가 아니라, "누구에게
켜줄지"를 별도 계층(화이트리스트)으로 분리**한다는 점에서 벤더 중립 코어 패턴의 변형으로
볼 수 있습니다(등급 c, 이 시리즈 내 유비 추론이지 NVIDIA가 공식적으로 이렇게 설명한 것은
아님).

## 4. 격상되지 않는 것 — 자기비판

- Streamline/NVIGI는 **소스 존재 유무**로 "닫힌 IP/열린 배관" 패턴을 실측 확인했지만,
  DLSS5는 소스도 헤더도 아직 없어서 **비교 대상 자체가 아직 성립 안 함**. 이 문서의
  "극단형"이라는 표현은 현재 시점 스냅샷일 뿐, 헤더가 나중에 공개되면 이 결론은
  무효화됩니다 — [[feedback_no_hardware_bias_in_future_expansion_analysis]]에서 강조한
  "재확인 전엔 최종 등급 승격 금지" 원칙을 그대로 적용해 등급 b 이상으로 올리지 않습니다.
